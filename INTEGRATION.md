# Cursor Usage integration

The app loads `https://cursor.com/dashboard/usage` in a persistent WebKit data store. Authentication takes place in the official dashboard flow. Only HTTPS navigation and the app's own blank page are allowed.

When the embedded page cannot finish a sign-in — typically a passkey that belongs to Google, GitHub, Apple or company SSO, which WKWebView offers only for domains associated with the app — **Sign in with external browser** runs Cursor's PKCE login in the default browser. The user-facing guide is [LOGIN.md](LOGIN.md). The app generates a random verifier, opens `https://cursor.com/loginDeepControl` with its S256 challenge, and polls `https://api2.cursor.sh/auth/poll` every two seconds for up to five minutes; 404 means the sign-in is still pending. The returned access token becomes the dashboard's `WorkosCursorSessionToken` cookie (`<WorkOS user>::<token>`, scoped to `cursor.com`, HTTPS only, expiring with the token) in the same persistent data store, so quota extraction and CSV import run unchanged. The tokens are stored in `browser-session.json` with 0600 permissions and renewed through `https://api2.cursor.sh/oauth/token` within a day of expiry; a refused renewal deletes them. These requests use an ephemeral URLSession.

Cursor does not document these endpoints. The embedded sign-in stays the primary path, a session the dashboard refuses is discarded with a prompt to sign in in the window, and disconnecting deletes the stored tokens along with the WebKit data.

Quota extraction reads the monthly allowance and renewal summary from text nodes, excluding scripts and styles. Export capture accepts only the official Cursor HTTPS host and the exact CSV endpoint `/api/dashboard/export-usage-events-csv`.

The CSV is parsed on a background queue. Import captures the UI's unknown-model label once, so parsing does not read mutable interface-language state. Pending downloads are deduplicated and cancellation invalidates pending callbacks. Partial files are removed on failure or cancellation; completed files are removed after parsing.

Metrics retain dates, model identifiers, cost, kind, and reported token counts. Raw email and repository columns are discarded; a digest identifies the account within an imported dataset. Multiple-account exports are rejected rather than combined.

Refresh intervals are one, five, or ten minutes, with five minutes as default. Countdowns and presentation update locally. Between completed synchronization cycles the dashboard WebView is released entirely. Persistent website storage keeps the session across those releases. Failures preserve prior valid observations and expose a retryable local status.

Per-model alerts read the same imported events. A model absent from `models-seen.json` is a first use; the first import only records the models in use. Each model's usual 15-minute spend is the median of its non-empty 15-minute windows over the last 14 days, needing at least four. The reference is the costliest of these, or a model the user picks; each model's pace is saved in `model-paces.json` (pace only, no events), so a picked reference that leaves the history uses its last saved pace. The threshold is a percentage or a dollar amount above the reference; the last 15 minutes before the import are compared with it, bursts under US$ 1 are ignored, and each model raises at most one rate alert a day. Monitored models compare today's and the cycle's spend with the user's goals. Rate and limit alerts require a fresh import; a first use does not. The model detail beside the card is a non-activating panel that ignores the pointer, so the card's hover and click handling is unchanged.

Goals and daily allowances use US dollars. Cycle/daily/renewal alerts are opt-in and deduplicated. The app does not infer missing daily data or zero usage from failed imports.

Saving presentation preferences updates local rendering without reloading the authentication page. The persistent WebKit session is independent of the system browser; federated accounts may require their organization’s sign-in and MFA policy. The app does not request or validate MFA codes itself.

Update checks run every hour and on demand, as anonymous HTTPS GET requests to the project's public GitHub latest-release endpoint. An ephemeral URLSession has no cookies or credential storage, with a 12-second timeout. Only HTTPS release links under this repository are accepted. Network errors, invalid responses and rate limits are never reported as an up-to-date result. Issue reporting opens the project's new-issue page without attaching data.

A newer release is announced once through a notification that carries its version; clicking it, on its body or on its Update now action, installs that version when it is newer than the running app. The update also stays offered in the card's footer, at the top of the status menu and as an accent-colored dot after the menu bar reading until installed; those signals are drawn by the app, so Focus or a utility that dismisses notifications cannot hide them. Hourly checks stay well below GitHub's anonymous limit of 60 requests an hour, and an announced version is not notified again. Installing downloads `CursorUsage-<version>-macOS-arm64.zip` and `manifest.json` from that release over an ephemeral URLSession, compares the archive with the manifest SHA-256, unpacks it with `ditto` into the app's own `update` folder in `~/Library/Application Support/CursorUsage/`, which sits on the same volume as Applications, and accepts the bundle only if its identifier matches, its version is the announced one, its code signature validates strictly and it carries no `com.apple.quarantine` attribute. The bundle is then swapped in place with `FileManager.replaceItemAt`; a helper shell waits for the old process to exit and reopens the app. A file the app downloads itself is not quarantined, so Gatekeeper does not reassess the ad hoc signature, for the same reason `install.sh` uses `curl`. Any failure leaves the running version untouched, and a location the app cannot write to falls back to the release page. That folder is deleted by path before the app exits, since termination skips deferred cleanup, and again at launch in case an update was interrupted. A fixed path matters: macOS does not let an app list its item-replacement folders, so a download left there could not be found and removed afterwards. At launch the app also removes update notifications for the installed version or older ones, so nothing of the previous version remains.

Every notice carries its route in its category and `userInfo`: update notices carry the version, model notices the model name, and goal and model notices a `kind`. `NotificationRoute` turns those into the place a click opens, so an action and a click on the body behave alike. Notices that arrive while the app is in front are shown as a banner and kept in Notification Center. Settings reads the authorization status and alert style with `getNotificationSettings` and explains them; the app never changes the style, it only links to the macOS page for its bundle identifier.
